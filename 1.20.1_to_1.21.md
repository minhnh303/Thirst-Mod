# Minecraft 1.20.1 to 1.21 Mod Migration Reference

## 1. Environment & Java Version
| Feature | Minecraft 1.20.1 | Minecraft 1.21 |
| --- | --- | --- |
| Java Version | Java 17 | Java 21 |
| Build Tool | ForgeGradle 6 / Java 17 toolchain | ForgeGradle 6 / Java 21 toolchain |
| Target Version | 1.20.1 | 1.21 |

## 2. ResourceLocation Construction
* **1.20.1**: Constructor `new ResourceLocation(namespace, path)` was public.
* **1.21**: Constructor is private. Use static factory methods:
  * `ResourceLocation.fromNamespaceAndPath(namespace, path)`
  * `ResourceLocation.parse(locationString)`
  * `ResourceLocation.withDefaultNamespace(path)`

## 3. ItemStack Data Components (NBT Replacement)
Vanilla Minecraft replaced general item NBT compound tags (`CompoundTag`) with strongly typed Data Components.
* **Deprecated/Removed Methods**: `stack.getTag()`, `stack.getOrCreateTag()`, `stack.setTag()`, `stack.hasTag()`.
* **Replacement API**:
  * Read: `stack.get(DataComponentType)` or `stack.getOrDefault(DataComponentType, defaultValue)`
  * Write: `stack.set(DataComponentType, value)`
  * Remove: `stack.remove(DataComponentType)`
* **Built-in Components**:
  * `DataComponents.FOOD` replaces older food properties query.
  * `DataComponents.POTION_CONTENTS` replaces the NBT `Potion` tag query.
  * `DataComponents.CUSTOM_DATA` holds a `CustomData` instance wrapping a `CompoundTag` for legacy/arbitrary data.
* **Custom Component Registration**:
  * Must implement immutable records that define `equals` and `hashCode`.
  * Registered using `DeferredRegister.createDataComponents(Registries.DATA_COMPONENT_TYPE, MOD_ID)`.
  * Must provide a `Codec` for serialization and a `StreamCodec` for synchronization.

```java
public record WaterPurityData(int purity) {
    public static final Codec<WaterPurityData> CODEC = RecordCodecBuilder.create(instance ->
        instance.group(
            Codec.INT.fieldOf("purity").forGetter(WaterPurityData::purity)
        ).apply(instance, WaterPurityData::new)
    );
    public static final StreamCodec<FriendlyByteBuf, WaterPurityData> STREAM_CODEC = StreamCodec.composite(
        ByteBufCodecs.VAR_INT, WaterPurityData::purity,
        WaterPurityData::new
    );
}

// In registration class:
public static final DeferredRegister.DataComponents DATA_COMPONENTS = DeferredRegister.createDataComponents(Registries.DATA_COMPONENT_TYPE, Thirst.ID);
public static final DeferredHolder<DataComponentType<?>, DataComponentType<WaterPurityData>> WATER_PURITY = DATA_COMPONENTS.register("water_purity",
    () -> DataComponentType.<WaterPurityData>builder()
        .persistent(WaterPurityData.CODEC)
        .networkSynchronized(WaterPurityData.STREAM_CODEC)
        .build()
);
```

## 4. FluidStack Component Support
* `FluidStack` now supports custom data components similarly to `ItemStack`.
* NBT methods on `FluidStack` are deprecated/removed in favor of `DataComponentHolder` methods:
  * Read: `fluidStack.get(DataComponentType)` / `fluidStack.getOrDefault(DataComponentType, defaultValue)`
  * Write: `fluidStack.set(DataComponentType, value)`
  * Remove: `fluidStack.remove(DataComponentType)`
* **Platform Difference**: In Classic Forge 1.21, legacy `FluidStack.getTag()` and `FluidStack.hasTag()` are still temporarily available but deprecated. NeoForge 1.21 has fully removed them.

## 5. LazyOptional & Capability Query Rework
* **Classic Forge 1.21**: Retains `LazyOptional` capability querying and `LazyOptional.of(...)` provider patterns.
* **NeoForge 1.21**: `LazyOptional` is completely removed. Capability querying returns direct objects or `null`.
* **Example (NeoForge)**:
  * **1.20.1**: `LazyOptional<IFluidHandlerItem> cap = stack.getCapability(ForgeCapabilities.FLUID_HANDLER_ITEM);`
  * **1.21 (NeoForge)**: `IFluidHandlerItem cap = stack.getCapability(Capabilities.ItemHandler.ITEM);` (direct return)
* **Caching**: Use `BlockCapabilityCache` instead of manually holding on to `LazyOptional` invalidation listeners.

## 6. Capabilities & Data Attachments
* **Registration**: `RegisterCapabilitiesEvent` in `net.minecraftforge.common.capabilities` is deprecated and marked for removal. Use the `@AutoRegisterCapability` annotation on custom capability interfaces.
* **Data Storage**: Storing custom data on entities, block entities, or chunks has migrated to **Data Attachments** (`AttachmentType` registered via `DeferredRegister` under `ATTACHMENT_TYPES` registry) on NeoForge. Classic Forge 1.21 still supports `AttachCapabilitiesEvent` for attaching `ICapabilityProvider` instances.
* **NBT Serialization**: Methods `serializeNBT()` and `deserializeNBT()` in capabilities or providers now require a `HolderLookup.Provider` parameter for registry context.

```java
// Custom capability interface
@AutoRegisterCapability
public interface IThirst {
    int getThirst();
    void setThirst(int value);
}

// INBTSerializable implementation update
public class ThirstStorage implements INBTSerializable<CompoundTag> {
    @Override
    public CompoundTag serializeNBT(HolderLookup.Provider provider) {
        CompoundTag tag = new CompoundTag();
        tag.putInt("Thirst", this.thirst);
        return tag;
    }

    @Override
    public void deserializeNBT(HolderLookup.Provider provider, CompoundTag nbt) {
        this.thirst = nbt.getInt("Thirst");
    }
}
```

## 7. Networking Overhaul (CustomPacketPayload)
Networking has been rewritten to align with `CustomPacketPayload` and `StreamCodec` patterns. The legacy `SimpleChannel` builder pattern (`messageBuilder`) is deprecated/removed in favor of `RegisterPayloadHandlersEvent` on the mod event bus.

### Step 1: Implement `CustomPacketPayload`
Packets should be implemented as Java `record` classes to guarantee immutability.

```java
public record PlayerThirstSyncMessage(int thirst, int quenched, float exhaustion) implements CustomPacketPayload {
    public static final Type<PlayerThirstSyncMessage> TYPE = new Type<>(Thirst.asResource("thirst_sync"));

    public static final StreamCodec<RegistryFriendlyByteBuf, PlayerThirstSyncMessage> STREAM_CODEC = StreamCodec.composite(
        ByteBufCodecs.VAR_INT, PlayerThirstSyncMessage::thirst,
        ByteBufCodecs.VAR_INT, PlayerThirstSyncMessage::quenched,
        ByteBufCodecs.FLOAT, PlayerThirstSyncMessage::exhaustion,
        PlayerThirstSyncMessage::new
    );

    @Override
    public Type<? extends CustomPacketPayload> type() {
        return TYPE;
    }
}
```

### Step 2: Register via Event
Use the `RegisterPayloadHandlersEvent` on the mod event bus. Get the `PayloadRegistrar` and register using `.playToServer`, `.playToClient`, or `.playBidirectional`.

```java
@SubscribeEvent
public static void registerPayloads(final RegisterPayloadHandlersEvent event) {
    final PayloadRegistrar registrar = event.registrar(Thirst.ID).versioned("1.0.0");

    // Clientbound sync packet
    registrar.playToClient(
        PlayerThirstSyncMessage.TYPE,
        PlayerThirstSyncMessage.STREAM_CODEC,
        PlayerThirstSyncMessage::handle
    );
}
```

### Step 3: Handle the Packet
Handlers must process payloads using `IPayloadContext`. Safe execution on the client/server main thread requires `context.enqueueWork()`.

```java
public static void handle(final PlayerThirstSyncMessage message, final IPayloadContext context) {
    context.enqueueWork(() -> {
        // Safe main thread execution
        Player player = context.player(); // Returns LocalPlayer on client, ServerPlayer on server
        // Apply sync values to player capability
    });
}
```

## 8. Loot Tables & Loot Context
* **Loot Table Retrieval**: Use `context.getResolver().get(Registries.LOOT_TABLE, resourceKey)` instead of `context.getLootData().getLootTable(resourceLocation)`.
* **Context Construction**: `LootContext.Builder` now requires `LootParams` during construction.

## 9. Creative Mode Tabs
* **Display Items Callback**: The display items generation signature changed:
  * **1.20.1**: `(displayParameters, output)` -> `output.accept(item)`
  * **1.21**: Uses `CreativeModeTab.ItemDisplayParameters` and `CreativeModeTab.Output`.

## 10. Registry & Resource Directories Depluralization
All registries and tags have been depluralized to use singular directories:
* `/tags/blocks/` -> `/tags/block/`
* `/tags/items/` -> `/tags/item/`
* `/tags/fluids/` -> `/tags/fluid/`
* `/recipes/` -> `/recipe/`
* `/advancements/` -> `/advancement/`
* `/loot_tables/` -> `/loot_table/`

## 11. Block & Item Interaction Results
* **1.20.1**: Many interaction handlers (like `CauldronInteraction`) returned standard `InteractionResult`.
* **1.21**: Introduces `ItemInteractionResult` for item-on-block interactions to differentiate between item-specific handling and general block interactions.
  * **Key Values**: `SUCCESS`, `CONSUME`, `CONSUME_PARTIAL`, `PASS_TO_DEFAULT_BLOCK_INTERACTION`, `SKIP_DEFAULT_BLOCK_INTERACTION`, `FAIL`.
  * **Usage**: Methods like `CauldronInteraction.interact` now return `ItemInteractionResult`.

## 12. Item Use Duration Signature
* **1.20.1**: `Item.getUseDuration(ItemStack)`
* **1.21**: `Item.getUseDuration(ItemStack, LivingEntity)`
  * *Important*: Overriding the single-argument signature in 1.21 will result in an overload, causing the method not to be called during item usage.

## 13. Enchantment System Rework
* **1.21**: Enchantments are now registry-based and stored on items as Data Components (`DataComponentTypes.ENCHANTMENTS`).
* **Damage Protection Calculation**: Calculating enchantment protection via `EnchantmentHelper` now requires dynamic context.
  * **Example**: `EnchantmentHelper.getDamageProtection(ServerLevel, LivingEntity, DamageSource)` replaces old level-based helper calls.
